## C. 15 Entity Implementation

**15/15 Tables Implemented.**

## D. PK/FK Strategy
All Primary Keys utilize PostgreSQL `UUIDv4`.
Foreign keys enforce the exact provenance chain from `Source` → `EvidenceRecord` → `[Specific Observation]`. Orphans are physically impossible to insert.

## E. ENUM Strategy
Enums (`PropertyType`, `GasSpecies`, `MissingnessStatus`, `StructureType`, `EvidenceClassification`, `VerificationStatus`, `ProcessingState`) are mapped to `sqlalchemy.Enum`. This rigorously secures the domain, ensuring that `OTR` cannot accidentally be written as `O_T_R`.

## F. Scientific Constraints
Conservative, scientifically defensible constraints were applied directly to the relational engine:
- `CheckConstraint` prevents negative transmission rates (`value >= 0`).
- `CheckConstraint` bounds EMAP thresholds natively (e.g. `target_o2_min_percent >= 0`).
- `CheckConstraint` protects material thickness (`thickness_value >= 0`).
- Bounds parsing variables (`value_min`, `value_max`) are mapped securely, preserving legitimate interval measurements without destructive scalar averaging.

## G. Indexes
Indexes (`index=True`) have been precisely added to lookup-heavy operational paths:
- Foreign Key join paths (`evidence_id`, `commodity_id`, `material_id`, `organism_id`, `source_id`).
- Phenotype isolation lookups (`property_type`, `property_name`, `gas_species`).
- Provenance/audit filtering (`evidence_classification`, `verification_status`).

## H. JSONB Usage
JSONB is securely deployed in explicitly permitted locations only:
- `EvidenceRecord.raw_json_payload` (archival)
- `EvidenceRecord.literature_references` (variable list)
- `EvidenceRecord.outlier_annotation` (textual reasoning)
- `PackagingMaterial.layer_sequence` (multi-polymer strings)
Newly defined semantic objects (like ComBase gas inhibition and Indian EMAP boundaries) are natively relational, NOT hidden in JSONB.
